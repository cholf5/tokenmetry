# 插件（私有 Agent）

Tokenmetry 内置约 20 个 Agent 数据源。如果你们公司内部有一个不在这个列表里的 Agent（下面
简称“私有 Agent”），可以用**数据源插件**把它的用量接进来：装好之后，它的数据会像内置 Agent
一样出现在总览、Agent、模型、项目、会话、时间与成本分析等现有页面里。

插件是本地第三方代码，由你自己手动安装，**不是插件市场**：官方不提供在线分发、自动更新或
IT 批量推送。

## 能做什么、不能做什么

**能**：

- 新增一个 Agent，并从它自己的数据位置（日志、SQLite、会话目录等）读取用量；
- 提供产品名、作者、图标等展示信息；
- 出现在「数据与计价」页的「插件」区块与数据源表里，状态与内置源一致（未扫描 / 扫描中 /
  未检出 / 部分数据 / 已连接 / 扫描失败）。

**不能**（v1 的产品边界）：

- 不新增页面、不改布局、不改查询与计价口径——固定信息架构不变；
- 不能自带默认价格（未定价的模型请在「数据与计价 → 模型目录」里配价或做别名映射）；
- 不支持 C# 以外的插件语言；一个插件包对应一个 Agent。

## 从哪来

插件由私有 Agent 的维护者（或你们的工程师）自己打包成 `.tkmplugin` 文件后交给使用者。开发
流程和工具都在仓库的 [`plugin-sdk/`](../plugin-sdk/README.md) 里：

- 作者指南：[`plugin-sdk/README.md`](../plugin-sdk/README.md)
- 交给工程师或其 AI 的完整工作流：[`plugin-sdk/SKILL.md`](../plugin-sdk/SKILL.md)
- 本地校验器：`dotnet run --project tools/Tokenmetry.PluginValidator -- validate <包>`

`.tkmplugin` 本质是一个 zip，包根目录包含 `plugin.json`、图标、入口程序集与依赖。官方应用
升级不会触碰已安装插件；面向 `apiVersion = "1"` 的插件在 v1 线内继续加载。

## 安装

1. 打开「**数据与计价**」页，滚动到「**插件**」区块，点「**安装插件…**」。
2. 选择 `.tkmplugin` 文件。应用会先做本地校验（包结构、manifest、API 版本、入口类型、图标、
   大小与文件数限制），失败会给出可读错误，不会留下“装了一半”的状态。
3. 阅读安装确认里的警告——**这是本地第三方代码**（原文见下），确认显示名、版本、作者
   （标注未验证）与 Agent 名无误后点「**确认安装**」。
4. 安装成功后插件默认启用，并立即触发一次扫描；状态会出现在插件区块与数据源表里。

> **安装警告原文**：这是本地第三方代码：它的运行权限与 Tokenmetry 相同，可以读取你的代码、
> 日志、会话内容，也可能访问网络；官方无法验证其来源。只安装来自可信来源的插件。

安装时只解压文件，不执行任何脚本。插件文件落在应用数据目录下的 `plugins/<id>/<version>/`，
插件自己的缓存另有独立目录。

## 管理

在「插件」区块对已安装插件操作：

- **启用 / 停用**：停用会停止该插件的宿主进程并把它移出扫描管线；插件文件、注册表条目与历史
  统计都保留。再次启用会恢复扫描。
- **刷新数据**：数据与计价页上的「重新扫描（全部源）」会把启用中的插件一起立刻跑一轮；v1 没有
  针对单个插件的重扫按钮。
- **卸载**：停止宿主进程，删除插件文件与插件缓存；**历史统计仍然保留**，已产生的事实不会消失。
- **升级**：安装同一个 `id` 的新包会被当作升级——校验通过后替换版本目录、重启宿主并做一次
  全量扫描。任何一步失败都保留上一版本可用。
- **改名注意**：v1 里插件的 `displayName` 是 Agent 身份的一部分。若新版本的显示名变了，安装
  确认会明确警告「该插件的 Agent 名从 X 改为 Y，历史数据会保留在 X 下」；旧数据不会自动迁移。

### 历史数据

停用或卸载插件都不会删除已经进库的聚合事实：这些数字继续计入统计。区别只在“以后还会不会
继续采集”。未安装某插件的历史 Agent（例如从另一台设备同步过来）会显示 Agent 名与兜底图标。

## 信任与安全边界

插件**不是**沙箱：

- 宿主进程以与 Tokenmetry 相同的用户权限运行；
- 插件能读写你的本机文件、访问网络，也有能力读取代码、日志、会话内容；
- v1 不做插件签名校验、官方认证、allowlist、进程沙箱或网络白名单。

因此只安装来自可信来源的包。插件只影响“数据从哪来”，不改变应用已有的隐私红线（Tokenmetry
自身只把聚合事实与配置写进 SQLite，不存 prompt / 代码 / 会话内容），但插件自身有能力读取这些
内容——安装警告会明确写出这一点。

插件异常不会传播到主进程：每个插件由独立的宿主进程加载，插件崩溃、卡死或超时只影响它自己
那条数据源，应用本体照常运行。

## 插件宿主不可用？

插件依赖随安装包分发的独立宿主进程（`plugin-host/`）。如果界面提示「插件宿主不可用（当前
安装包未包含插件宿主）」，通常是因为你在**开发构建**里直接 `dotnet run`——开发输出目录不含宿主。
正式安装包与 zip 都带宿主。本地联调请先按 `scripts/package.sh` 打一个包，或用校验器的
`validate` / `scan` 直接驱动宿主。

## 已知限制

插件 v1 的体积、无签名 / 无沙箱、改名切历史、不能自带价格等限制，逐条写在
[`release/known-limitations.md`](release/known-limitations.md) 的「七、插件（v1）」一节。
