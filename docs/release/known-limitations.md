# 已知限制（v0.3.2 起，最近更新 v0.6.0）

> 当前发布时点已知、**明知就不修**或**排在后面**的问题。每一条都写清：用户看到什么、什么条件下会撞上、
> 现在怎么绕、后续怎么收。定位见 [`../kanban/roadmap.md`](../kanban/roadmap.md)，架构与口径约定见
> [`../../AGENTS.md`](../../AGENTS.md)。

原则：宁可写成文字，也不假装没有。首版的目标是"数字对得上、口径说清楚"，不是"没有坑"。

## 一、数字可信度

### 1. 读失败会被静默吞掉，界面仍报正常

**症状**：某个 Agent 的日志读不动（权限、文件被占用、磁盘错误、格式意外），该源这一轮直接少报甚至归零，
界面上仍是正常状态、没有告警。你不知道自己看到的是"今天真没花这么多"还是"没读到"。

**原因**：适配器与解析器内部对 `IOException` / `UnauthorizedAccessException` 有二十余处兜底
（`Tokenmetry.Infrastructure` 内 27 处），失败即"这条跳过、继续下一条"，不改变扫描状态；
只有解析器整体抛出的异常才会被 `LocalIngestionDataSource` 的逐源隔离登记为 `Error`
（`JsonlScanStatus.Error` 只由那一处产出）。

**现在怎么绕**：怀疑某个源少报时，去「数据与计价」页看该源的文件数与记录数；数字长期冻结再看一眼文件是否可读。

**后续**：把"部分读取失败"升级成 `Partial` + 计数（哪些文件、失败原因），在数据页可见。

**0.6.0 起的状态**：解析层面的失败（畸形行、坏记录、文件解析异常）现在会把该源标成「部分读取」，
数据页可见（含记录数/文件数）；`IncrementalJsonlScanner` 按 `MalformedLines / InvalidRecords / 解析异常文件集`
三项判 `Partial`。**残留**：适配器层 `IOException` 仍是逐文件跳过、不进计数——所以"少报了"仍可能
不体现在状态上。这条因此降级为部分修复，不再是"发版后第一优先"，但也没归零。

### 2. Kimi / DSH 的时间戳未做范围钳制，一条坏数据能让整个源停摆

**症状**：这两个源某天开始一直显示红/异常，且不会自愈——即使后续日志都是好的。

**原因**：`KimiLogParser.TimestampFromSeconds` 与 `DshSessionLogParser` 直接调
`DateTimeOffset.UnixEpoch.AddMilliseconds(...)` / `FromUnixTimeMilliseconds(...)`；日志里出现一个
超出 `DateTime` 表示范围的毫秒值（损坏行、错位字段）就抛 `ArgumentOutOfRangeException`，
整轮解析失败 → 该源进 `Error`，下一轮同样的坏行再抛一次。
Kilo / Hermes / Goose / OpenCode 都有 `TimestampOutOfRange` 拒绝枚举兜底，这两个源没有。

**现在怎么绕**：找到并移走那条坏日志文件（或在设置里临时关掉该源），重扫后恢复。

**后续**：照四个 SQLite 源的做法补拒绝枚举，坏行进"被拒记录数"而不是让整源失败。

### 3. Antigravity 在 WAL 未 checkpoint 时数字会冻结 —— **已在 0.6.0 修复（留档）**

**症状**：Antigravity 正在使用、新会话也产生了，但 Tokenmetry 里的数字不动，重启应用或过一阵才跳变。

**原因**：Antigravity 是 proto 日志库直读，增量判据是文件戳（mtime + 大小），而它取戳的清单只含主库
（`AntigravityAdapter` 走 `FileStampMemo.Capture(databases)`）。SQLite 的写入先落 `-wal` 边车，主库
mtime 在 checkpoint 前不变——只看主库就会判定"没变化"。另外六个 SQLite 源用的是
`FileStampMemo.SqliteFingerprintFiles`（主库 + `-wal`），没有这个问题。

**现在怎么绕**：点一次「立即刷新」或重开应用（首轮不做指纹复用）。

**后续**：Antigravity 改用 `SqliteFingerprintFiles`。

**0.6.0 已按此收口**（I-048）：指纹清单改为 `FileStampMemo.SqliteFingerprintFiles`（主库 + `-wal`），
与另外六个 SQLite 源逐字同口径。留在此处只为对照历史症状；新增回归测试见
`AntigravityAdapterTests.ChangeProbe_WalSidecarTouched_DetectedAsChange`。

### 4. `grain='full'` 快照行只 upsert、从不删除 —— 时区/夏令时变更后可能双算

**症状**：改过系统时区（或经历夏令时切换）后，某些日子的总量偏高，像是同一批用量被算了两遍。

**原因**：`usage_facts` 有两类行：分解粒度（`grain <> 'full'`，可按日清理，`SqliteUsageStore.cs:274`）
与全量快照（`grain = 'full'`，只 `UPSERT`）。快照行按 UTC 自然日分桶，日志里的时刻重新落到另一个
UTC 日期时，旧日期那一行没有任何清理路径把它带走。

**现在怎么绕**：清空数据目录下的 `tokenmetry.db` 让它全量重建（会丢失历史会话级明细，聚合数字重建后一致）。

**后续**：给快照行加"本轮日期集合"对账删除。**建议作为发版后的第一张卡**——这是清单里唯一会让
信任锚失真的问题。

## 二、启动与常驻

### 4b. 便携版仍会向临时目录解包原生库

**症状**：Windows 便携 zip 与 Linux 单文件包首次启动时会往临时目录写约 20MB（Windows：
`%TEMP%\.net\Tokenmetry.App\<哈希>\`），之后启动复用；每次更新版本会再写一份新的。

**原因**：单文件包里的原生库（Skia / HarfBuzz / SQLite）无法从内存加载，只能先落盘——
这是“一个文件就能跑”的对价。**安装器与 macOS .app 从 v0.3.2 起改成 AOT 散开形态，不碰 temp**。
（便携 zip 自插件版起还带 `plugin-host/`，它是多文件 self-contained 目录、不向 temp 解包；这里说的是主程序单文件本身。）

**现在怎么绕**：想要无 temp 解包就用 Windows 安装器，或用 macOS 版。

**后续**：Linux 是否转 AOT 待真机验证（见第 12 条）。

### 5. 没有全局异常处理器，崩了不留证据

**症状**：应用突然消失，没有对话框、没有日志，你无法告诉作者发生了什么。

**原因**：`App` 没有订阅 `AppDomain.UnhandledException` / `Dispatcher.UnhandledException`，也没有
崩溃转储文件。UI 线程上的意外异常直接掀翻进程。

**现在怎么绕**：终端里 `dotnet run --project src/Tokenmetry.App` 启动，异常会落在终端。

**后续**：捕获 → 写本地 `crash-*.log`（不含 prompt/代码，符合隐私红线）→ 下次启动提示"可附上报告"。

### 6. 冷启动期的"双击图标没反应"

**症状**：第一次启动还没起来的那几秒内再双击一次图标，第二次双击像被吞了，窗口不会更快出现。

**原因**：第二实例的激活监听在主窗与托盘就绪之后才启动（`App.axaml.cs:131` 的 `StartListener`）。
在此之前第二实例只能靠重试窗口盲发（`SingleInstanceGuard.TrySignalActivation`：3 次尝试、每次连接与
回执各 1.5 秒），超时即静默退出——按设计它不该抢占首实例，所以退出是正确的，只是没有反馈。

**现在怎么绕**：等首实例启动完成（托盘图标出现）再操作。

**后续**：第二实例失败时给一次短提示，或把监听提前到窗口创建之前。

### 7. 托盘弹层：点走焦点后 400ms 内点托盘会被吞一次

**症状**：弹层正开着时先点了别处（弹层失焦关闭），紧接着点托盘图标，第一次没反应。

**原因**：`StatusPopoverController` 的焦点丢失守卫（`FocusLossToggleGuard`，400ms）。这是有意的取舍：
macOS 上"失焦自动关闭"与"点击即切换"会撞成开-关-开的抖动，守卫用 400ms 换稳定手感。

**现在怎么绕**：隔半秒再点。

## 三、界面与文案

### 8. 会话表的 `Token` 列头是硬编码英文

**症状**：切到中文/日文等其他语种，会话表这一列表头仍是 `Token`。

**原因**：`Views/SessionsView.axaml:66` 直接写了 `Text="Token"`，没走 `Translations`。这是 i18n 纪律
（文案唯一出处 `Localization/Translations.cs`）的一处漏网。

**后续**：进 `Translations` 全语种补 key——注意 `TranslationsTests` 会强制 10 个语种全覆盖。

## 四、分发与安装

### 9. 包都是未签名的

**症状**：Windows 上装安装器时 SmartScreen 提示「未知发布者」；macOS 首次打开 `.app` 提示
`"Tokenmetry" 无法验证开发者`；部分企业环境/杀软会直接拦掉下载或启动。

**原因**：没有代码签名证书（Windows EV 证书 / Apple 开发者账号都是付费且需实名）。macOS 产物是最小
`.app` bundle + ad-hoc 签名，只保证不报「已损坏」，不消除上面那个提示。

**现在怎么绕**：

- Windows：安装器 →「更多信息」→「仍要运行」。
- **macOS 26（Tahoe）已没有“右键 → 打开”这条捷径了**：右键打开会直接告诉你用不了，唯一的图形界面
  路径是「系统设置 → 隐私与安全性 → 滚到最下面 →『仍要打开』→ 输开机密码」，再双击一次确认。
  所以文档把**终端那条排在第一位**——一行 `xattr -cr` 就把 quarantine 标抹掉，之后双击直接过，
  不分系统版本、不用找菜单：

  ```bash
  xattr -cr /Applications/Tokenmetry.app
  ```

  若 App 不在应用程序目录，换成实际路径。彻底不想碰 Gatekeeper 的话，直接从源码跑：
  `dotnet run --project src/Tokenmetry.App`。
- Linux：解压即用。

**后续**：买证书 / Apple 开发者账号后接进 `package.sh`（macOS 还需公证 + staple）。付费前提，不是代码问题。

### 10. 安装器只有 Windows 有，向导也只有英文

**症状**：Linux 没有 `.deb` / `.rpm` / AppImage；Windows 安装向导的按钮与提示是英文，而应用界面本身
可以是中文。（macOS 不发 `.dmg` 是**已决策不做**，不是缺口——见第 13 条。）

**原因**：Linux 各包格式要各自的仓库与依赖体系，没有用户需求时不值得做。向导语言：Inno Setup 官方
只内置英文，中文要非官方 `chinesesimplified.isl`——而应用内静默升级根本不显示向导，价值不在首位。

**后续**：Windows 向导中文可以随时补（一个 `.isl` 文件）；Linux 包格式待有用户需要再谈。

### 11. 更新在 macOS / Linux 仍是「下载 + 自己解压」——v0.4.0 已解决

**v0.4.0 起应用内一键更新覆盖全平台**：便携版 / macOS / Linux 由 UpdateStager 做同卷 rename
原子替换（失败回滚）。便携 zip / Linux 把主程序与 `plugin-host/` 作为整体一起换（任一失败阻塞或回滚，
不会出现“新主程序配旧宿主”）；macOS 替换整个 `.app`。下载强制 SHA-256 对账，重启后按
`update-state.json` 判定成败并给备份路径。剩余两条边界：目标目录不可写（`/Applications` 只读、企业策略）
时退回「下载 + 文件管理器显示」手动替换；v0.3.3 及更早的老版本没有自动替换能力，升到 v0.4.0 的那一次仍要手动解压覆盖。

（历史记录）v0.3.x 只有 Windows 安装器可以接管替换：macOS 的 `.app` 可以在运行中被替换（目录可卸），但没有
安装器就没有可靠的回滚与“关旧实例→换文件→重启”流程；Linux 则连统一分发格式都没有。

### 12. Linux 主程序仍是单文件 R2R，AOT 未真机验证

**症状**：Linux 包比 AOT 形态大得多（约 66MB zip，另加插件宿主的几十 MB），首次启动主程序还会向临时目录解包原生库。

**原因**：macOS 与 Windows 的 AOT 产物都已人工验过（窗口 / 托盘 / 图表正常），Linux 没有；
CI 只能做 `xvfb` 启动冒烟（进程存活 + 建库），验不了画面与托盘。

**后续**：拿到一轮 Linux 真机反馈后切 AOT；改动只有 publish 参数，其余与 macOS 同构。

### 13. macOS 仍发 zip，不做 `.dmg`（已决策，含重开条件）

**结论**：macOS 继续发 `Tokenmetry-{版本}-osx-{arch}.zip`，不改成 `.dmg`。这是决定，不是排期缺口——
不要再把它当成待办或“体验债”摘回去重新评估。

**为什么收益不明显**：

- **步数上不赚。** 现在 zip 只有一个顶层条目 `Tokenmetry.app/`，Finder 解压后 app 直接落在原地：
  双击 zip → app 出现在旁边 → 双击运行 / 拖去 Applications，三步。dmg 是双击 → 等挂载 → 拖 → 推出
  镜像，四步。dmg 唯一的真本事是那张“往右拖”的示意图在教用户怎么做。
- **换不来信任。** Mac 上的信任信号是签名与公证，不是容器格式。没有证书时，两种格式首次打开弹的是
  同一句“无法验证开发者”——漂亮的 dmg 只是在漂亮的无背景窗口里弹同一个警告。
- **体积还略大。** 实测同一份 R2R `.app`（189MB）：dmg 74MB、zip 66MB（UDZO 对里面已压缩的原生库
  不如 deflate 划算）。
- **成本在契约面，不在那 4 行 `hdiutil`。** 资产名要同步改 `UpdateAssets.cs` / `ci.yml` /
  `package.sh` / `release.sh --watch` 四处，下载完整性校验也得改（dmg 开头没有魔数，标识 `koly`
  在文件末尾 512 字节）；而这条路径（应用内下载 macOS 资产）发版前在本机验不到，只能靠发版后真机点
  一次——为格式美观去沾一条“只能事后验证”的改动，不划算。

**什么时候重开**（满足任一条再做）：

1. 有 Apple 代码签名与公证了——那时 dmg 才能给出“打开就是干净的拖拽窗口、无警告”的完整体验；
2. 有 macOS 用户反馈“下下来不知道怎么装”；
3. 某次本来就要动 `package.sh` 的 mac 分支，顺带做（边际成本最低，但下载校验那条仍要单独验）。

**替代投入**：同样半天，花在第四条（快照双算）上对“数字可信”这个信任锚的价值远高于换容器格式。

## 五、同步与排行榜（0.6.0 新增，均为 opt-in）

### 14. 官方实例暂未开放：设置页入口置灰，同步只能走自建中继

**症状**：设置页 →「跨设备同步」，「官方实例」单选项置灰不可选，下方提示自行部署中继服务器；可用通道只有「自建中继」。

**原因**：官方实例依赖编译期常量 `TokenmetryOfficial.GitHubClientId` 与 `OfficialRelayUrl`，本版两者
都是空串。产品短期内没有部署官方实例的计划，因此客户端把入口直接标成未开放，而不是留一个点了才
报错的按钮。

**现在怎么用**：用**自建中继**（[`../selfhost.md`](../selfhost.md)，一条 `docker run`，地址与 token 填进
设置页「自建中继」）。多台设备填同一地址 + 同一 token 即为同一个账号；要让朋友各自独立，用中继的
`token add --name <展示名>` 签发成员 token，或在自建中继的 `/admin` 管理页（运营者 token 登录）添加
（见 selfhost.md「多用户」/「Web 管理页面」）。

**后续**：将来部署官方实例时把两个常量填上并出一版——入口自动恢复可选（视图按 `IsAvailable` 判定），
客户端不需要其它改动。

### 15. 官方榜单网页未上线；自建中继自带 `/leaderboard`

**症状**：`https://tokenmetry.app/leaderboard` 目前 404；官方实例与公共榜单尚未上线。

**原因**：官方中继与站点榜单页尚未部署；本版只有客户端、中继后端与自建页面。

**现在怎么用**：自建中继自带只读榜单网页，打开 `http://<你的中继>:8080/leaderboard`（反代后即你的
https 地址）就能看当月 Token 榜 / 金额榜与历史月份；设置页「在网页查看」在自建连接下会直接打开你的
中继页面。榜单只显示显式 opt-in 的账号。

**后续**：官方网页榜单随官方中继一起上线；届时本节点删除。

### 16. 中继可读明文（不做端到端加密）

**症状**：不体现在界面上，是信任边界问题——开了同步，中继持有你的聚合事实行明文。

**原因**：刻意"笨"的中继：它要做 LWW、设备对账与月度 rollup，端到端加密会让这些全部落到客户端
（成本远超收益）。过线的只有聚合事实（日粒度 token/成本行）与设备元数据，不含 prompt、代码、会话内容。

**现在怎么绕**：只指向你信任的中继；自建是最稳妥的形态（服务器归你）。关掉同步即停止一切出站。

**后续**：不做。这是决策，不是排期缺口。

### 17. 从 0.6.0 降级回 0.5.x 前必须先备份数据目录

**症状**：装回 v0.5.0 后它对着迁移 3 之后的库运行，设备维度列与主键它不认识。

**原因**：迁移只前进不回滚（`schema_migrations` 账本就是全局版本）。0.6.0 把 `device` 加进
`usage_facts` / `session_facts` 主键并回填本机 id；旧版本的 SQL 与主键假设对不上。

**现在怎么绕**：降级前把 `%LOCALAPPDATA%\Tokenmetry\tokenmetry.db`（macOS/Linux 见设置页「打开数据目录」）
复制一份；真降级就用旧版本重建库（历史会话级明细会丢，聚合数字重建后一致）。

**后续**：不做（跨大版本的向后兼容不在契约里）。

### 18. 旧版中继没有设置同步端点

**症状**：客户端打开「同步应用设置」后状态行显示同步失败（`404`），且这一轮的用量同步也一起被标失败。

**原因**：应用设置同步是 v1.2 新增的 `GET/PUT /api/me/settings`；旧版中继没有这两个端点。
失败会把整轮同步记为失败并按既有退避重试（同一轮里事实与设置共享错误出口）。

**现在怎么绕**：把中继升级到同一版本（重新部署二进制即可；`account_settings` 表随建库幂等补上，
不需要迁移）；暂时不用就保持开关关闭（默认关，零出站）。

**后续**：中继版本协商能力（v1 保持"同版本部署"约定，不在客户端做降级分支）。

## 六、内部小瑕疵（不影响日常使用）

- CI 的 test job 只跑 `ubuntu-latest`（windows/macos job 只负责打包）——**CI 绿 = Unix 绿**。
  0.6.0 收口时才发现 Windows 上 `dotnet test` 有 9 条红（日志读取与临时库收尾的文件共享冲突），
  已修；但"跨平台测试只在 ubuntu 上把关"这个结构性问题仍在。
- 迁移 2 的 `DROP TABLE usage_facts` 缺 `IF EXISTS`（迁移 1 有）。只在 `usage_facts` 不存在的库上才会炸，
  而迁移 1 一定会先建它——所以是洁癖级问题，不是隐患。
- 首次发版没有上一个 tag，`gh release create --generate-notes` 会把整个提交历史抖出来。首版用
  [`notes/v0.3.0.md`](notes/v0.3.0.md) 手写说明（CI 已支持 `docs/release/notes/<tag>.md`）。
- Windows 安装器从 v0.3.1 起提供：v0.3.0 的 Windows 用户要手动跑一次安装器才能进入「可静默升级」状态
  （安装到 `%LOCALAPPDATA%\Programs\Tokenmetry`，数据不受影响；旧 zip 目录可自行删掉）。

## 七、插件（v1，2026-11-23 新增）

设计见 [`../plans/2026-11-23-custom-agent-plugin-design.md`](../plans/2026-11-23-custom-agent-plugin-design.md)
（本地文档，不入库）；用户侧说明见 [`../plugins.md`](../plugins.md)。

### 19. 插件宿主让每个包多几十 MB

**症状**：带插件宿主的版本，Windows / macOS / Linux 三个产物（以及 Windows 安装器）都比之前大几十 MB，
且三平台各自带一份完整的 self-contained CoreCLR 运行时。

**原因**：主应用是 Native AOT，不能动态加载插件程序集，所以插件由随包的独立宿主进程
（`plugin-host/Tokenmetry.PluginHost[.exe]` + 依赖）加载。宿主是普通 CoreCLR、非 AOT，自带运行时；
它随应用更新一起替换，不单独更新。

**现在怎么绕**：没有开关能从包里剔除宿主；不用插件的人也会承担这份体积。这是“插件故障不拖垮主进程、
主应用保持 AOT”的直接对价。

**后续**：评估宿主裁剪或共享运行时、按需下载，但不会为了体积把插件塞回主进程。

### 20. 插件没有签名、没有沙箱

**症状**：安装任何 `.tkmplugin` 都会弹出「本地第三方代码」警告并要求确认；应用不验证来源、也不隔离权限。

**原因**：v1 不做插件签名校验、官方认证、allowlist、进程沙箱与网络白名单。宿主进程与 Tokenmetry
同用户权限运行，插件可读写本机文件、访问网络，也有能力读取你的代码、日志、会话内容。

**现在怎么绕**：只安装来自可信来源（公司内部或你信任的作者）的插件；来源不确定就不要装。

**后续**：签名 / 证书链 / 沙箱是后续版本的工作，不是 v1。

### 21. 插件改显示名会切断历史

**症状**：插件升级时改了 `plugin.json` 的 `displayName`，安装后旧数据仍在旧 Agent 名下、新数据进新
Agent，统计看起来“分家”了。

**原因**：v1 里 `displayName` 是 Agent 身份的一部分（facts 的 Agent 键）。安装 / 升级时应用会警告
「该插件的 Agent 名从 X 改为 Y，历史数据会保留在 X 下」，但不会自动迁移。

**现在怎么绕**：要延续历史就保持 `displayName` 不变；确实要改名时接受历史分段，或清库重建
（聚合数字重建后一致，但会丢会话级明细）。

**后续**：给 facts 引入稳定的插件 id 维度并做迁移，是 v2 候选。

### 22. v1 插件不能提供价格

**症状**：插件接入的内部模型在成本列显示「未定价」，总成本偏低。

**原因**：v1 刻意不让插件自带默认价格——计价是信任锚，必须由应用统一管理。插件只提供 token 与模型名。

**现在怎么绕**：在「数据与计价 → 模型目录」里给内部模型配价，或用别名映射到已有定价模型。

**后续**：是否允许插件提供“建议价格”留待评估；应用侧的用户覆盖仍是最终口径。

### 23. 开发构建没有插件宿主

**症状**：直接 `dotnet run --project src/Tokenmetry.App` 时，「数据与计价」页的插件区块显示
「插件宿主不可用（当前安装包未包含插件宿主）」，无法安装或运行插件。

**原因**：主应用不引用宿主项目（AOT 边界），`dotnet run` 的输出目录里没有 `plugin-host/`。只有正式
安装包 / zip 经 `scripts/package.sh`（或 CI）把宿主放进 `plugin-host/`。

**现在怎么绕**：本地要试插件，先跑 `scripts/package.sh --rids <rid>` 打一个包；或用校验器的
`validate` / `scan` 直接驱动宿主（它会把宿主复制到自己的输出目录）。

**后续**：可考虑给 Debug 构建加显式复制宿主的开关，但默认不把宿主塞进开发输出，避免 AOT 边界被顺手破坏。

### 24. macOS 自更新后嵌套插件宿主的签名会失效

**症状**：不体现在界面上。用应用内更新（下载 + 重启）升级 macOS 版后，`codesign --verify` 会报插件宿主里的 .NET 程序集未签名；而从 Finder 双击发布 zip 首次安装的副本是有效的。

**原因**：插件宿主是 self-contained CoreCLR 目录，里面约两百个 `.dll` 是 .NET PE 程序集。codesign 对 PE 程序集的签名存放在**扩展属性**（`com.apple.cs.*`）里，不是文件内容。发布 zip 用 `ditto` 归档以保留 xattr（Finder / Archive Utility 解压会还原）；应用内更新用 `ZipFile` 解包，xattr 因此丢失。应用与插件照常运行（macOS 不在启动时校验嵌套代码，且产物本就是 ad-hoc 签名、未公证），只是签名封条不再完整。

**现在怎么绕**：在意签名完整性的 macOS 用户用发布 zip 手动覆盖安装（Finder 解压）；应用内更新不影响功能。

**后续**：让 macOS 自更新改用保留 xattr 的解包方式，或解包后对宿主重新做 ad-hoc 签名。
