# Tokenmetry v0.7.1

**新增宿主（Host）维度：Agent 是执行引擎，宿主才回答「谁发起」——Cindy 三路 runtime 全量入账；代理网关的多 block 响应不再重复记账；分享海报跟随应用画板换色。**

## 这一版有什么

**宿主维度：把「用什么引擎跑」和「谁发起」分开**

- 以前只有 Agent 一个维度：Cindy 借 Claude Code / Codex 当 runtime 时，数据记在 Claude Code / Codex
  名下，和你在终端里直接用它们无法区分；Cindy 私有的 Codex home 更是从未被扫描，那部分用量直接漏采。
- 现在两级口径：**Agent 永远是执行引擎**（Claude Code / Codex / Pi 等），**Host 表示发起宿主**
  （`Cindy`；空串 = 本机 CLI / 未识别）。同一引擎的 Cindy 会话与终端会话分行记账，不再混在一起。
  后续 T3 Code、Orca Agent 这类「宿主套引擎」的产品按同一模型接入，不再复制适配器。
- 采集覆盖：Cindy userData 区域（`Cindy` / `CindyGlobal` / 历史 `xdt-maker`；`CindyDev` 是开发者身份、
  有意排除）、`CindyHost/<profile>`、以及 Cindy 私有 Codex home（`codex-home`、
  `codex-accounts/<owner>/<provider>`）。跨 home 按 rollout 逻辑身份去重——同一 rollout 被 Cindy
  收养只计一次，恢复出来的 `rollout-cindy-*` 伪文件让位原文件。
- 归属仲裁：只读 Cindy 本地 owner 库里**会话元数据**（session id、project_dir、working_dir、
  workspace_kind），**绝不读消息内容**；库指纹没变时不发 SQL，读取失败沿用上一版成功索引并在下轮重试。
  没有 owner 库就不猜归属（记为空串）。
- 界面：顶栏新增「宿主」筛选（含「本机 CLI」一项，即空宿主）；Agent 页每个 Agent 下显示宿主拆分
  占比；会话列表与会话详情显示宿主徽标；十种语言文案齐全。
- 历史数据：迁移 5 自动执行，旧行宿主留空（按「本机 CLI / 未识别」展示），重新采集覆盖到的日子
  按新口径重算；清库重建同样安全。

**代理网关的多 block 响应只记一次账（Claude Code）**

- 症状：经代理网关调用 `deepseek-*` 时，Claude Code 会把一次 API 响应按 content block
  （thinking / text / tool_use…）写成多行 assistant 记录，共享同一 `message.id` 与 usage。
  旧去重口径把时间戳并进键，同一响应被记多次——实测单会话 2398 条 usage 行只对应 1110 个
  请求，约 2.1 倍。
- 修复：按转录的 `uuid → parentUuid` 响应链归属，同一响应只记一次；有 `requestId` 的路径与
  sidechain 回放口径保持不变。对齐 ccusage 20.1.1（其 #2341 修的同款问题）。
- 受影响用户的 Claude 数字会回落——这是修正重复计数，不是丢数据。

**分享海报配色跟随应用画板**

- 此前海报不论应用选哪套画板，预览与导出的都是同一套默认蓝色；现在海报跟随当前画板
  （Nord / Dracula / Catppuccin / Tokyo Night 等），明暗仍有三态可选，单档画板按既有约定回落。
  热力色阶、里程碑辉光与图表系列色保持数据语义色，全画板恒定。

**开发侧**

- 新增 ccusage 对账的仓库级 skill，对账入口与录制命令收敛到单一出处。
- 真实数据对账用例对齐 A-0b 与对账文档 §6 的有意分歧：ZCode / DSH 在装有对应数据的机器上
  不再持续误报（tokens 仍全量精确对账，成本只比较可计价行）。
- 新增 Host 维度查询、归属索引、迁移与 relay 升级、同步 epoch 清库等覆盖。

## 升级须知（重要）

- **自建中继必须与客户端同版本**：Host 维度改变了同步行身份（`usage_facts` 主键新增 `host`）。
  请**先升级中继、再升级客户端**；新版客户端在升级后的首次同步会推一份整份快照，中继据此清掉
  本设备迁移前的旧行并推进 `data_epoch`，其它设备看到 epoch 变化会先清该设备本地副本再接收。
  顺序反了（客户端先升、中继还旧）不会报错，但这次整份快照会被旧中继当普通增量吞掉，旧行
  可能留成幽灵——补救办法是把中继升到本版后，在客户端把同步关掉再打开（重新开启会复位推送
  游标，触发整份快照重推）。升级窗口内最稳妥的做法是先关同步。
- **迁移 5 / 6 在启动时自动执行**，无需手工操作。历史行保留空宿主是语义诚实：旧记录里没有
  宿主标记，不猜。
- **不要降级回 0.7.0**：旧版 SQL 的冲突目标不含 `host`，对着迁移 5 之后的库会直接失败。
  真要降级，先备份数据目录（设置页「打开数据目录」），必要时清库重建。

## 已知限制

完整清单见 [`docs/release/known-limitations.md`](docs/release/known-limitations.md)。本版要紧的五条：

- **中继与客户端要一起升级**（上面「升级须知」），旧中继会按旧主键把不同宿主的行合并。
- **插件是本地第三方代码，没有签名、没有沙箱**：宿主与 Tokenmetry 同用户权限运行，插件可读写本机
  文件、访问网络，也有能力读取代码、日志、会话内容。只安装来自可信来源的包。
- **包都未签名**：Windows 安装器触发 SmartScreen「未知发布者」（→「更多信息」→「仍要运行」）；
  macOS 是 ad-hoc 签名，**全新安装**首次打开会被 Gatekeeper 拦一次。macOS 26 已没有「右键 → 打开」
  捷径，最省事的是终端一行：

  ```bash
  xattr -cr /Applications/Tokenmetry.app
  ```

- **Linux 版仍是单文件 R2R**（AOT 未真机验证）；**读失败仍可能被逐文件跳过**，数据页能看到「部分
  读取」但不保证每个 `IOException` 都有计数。
- **时区/夏令时变更后的快照行残留**（第 4 条）还剩边界：本版起，本轮有记录的 agent × 日会清掉
  已不存在的快照行；但时刻整体落到「本轮没有记录」的日期时，旧行仍可能留下。清库重建可根治。

## 数据与隐私

SQLite 只存聚合事实与配置，不存 prompt、代码、会话内容；**默认零网络**——价格目录刷新与应用内更新
检查之外不发请求。跨设备同步、设置同步与排行榜都是显式 opt-in 的例外：关闭即本地纯离线，开启后
过线的只有聚合事实、设备元数据与偏好值，中继可读明文（不做端到端加密），所以只该指向你信任的中继。

本版新增的「宿主归属」只读 Cindy 本地 owner 库的**会话元数据**（session id、项目路径、workspace
类型）来做归属判断，不读消息内容；读到的只有归属结果（宿主名与项目名）进入聚合事实，原样遵循上面的
隐私红线。
