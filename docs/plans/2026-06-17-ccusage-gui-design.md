# GUI 版 ccusage 设计草案

## 背景

`ccusage` 是一个非常好用的 CLI token/cost 统计工具，已经证明了本地 AI coding usage 数据的价值。但它是终端工具，天然挡住了很多不熟悉命令行的用户，也无法主动提醒用户成本异常。GUI 版的机会不只是把 CLI 表格搬到图形界面，而是把它产品化成一个本地优先、隐私友好的个人 AI 编程成本监控器。

本设计面向第一版 MVP，目标是验证个人用户是否需要一个常驻桌面工具来持续监控 Claude Code 和 Codex 的 token 与成本。

## 产品定位与 MVP 边界

这个 GUI 项目不应被定位成“ccusage 的表格可视化”，而应定位成一个**开源、本地优先、隐私友好的个人 AI 编程成本监控器**。它面向的第一批用户是个人 AI 编程用户，尤其是每天使用 Claude Code 和 Codex 的人。它解决的问题不是“有没有 token 数据”，而是“我不用打开终端，也能持续知道 AI 编程花了多少钱、是否异常、钱主要花在哪”。

第一版采用桌面 App 形态，目标平台是 macOS + Windows。产品体验上优先做常驻托盘/菜单栏和系统通知，而不是只做一个被动 Dashboard。默认只开启异常型提醒，预算提醒和实时活跃提醒提供设置但默认关闭，避免通知噪音。MVP 数据源只支持 Claude Code + Codex，不承诺 all-agent 全覆盖。项目以完全开源免费启动，强调本地处理、不登录、不上传数据，以建立用户信任。

第一版成功标准不是功能全面，而是用户安装后能做到：后台自动刷新、托盘看到今日/月度成本、异常时收到提醒、点击后能查看成本趋势和主要来源。

## 推荐架构与技术路线

建议采用 **Tauri 2 + Web 前端 + Rust 后端直接集成 ccusage core** 的架构。前端负责 Dashboard、图表、设置页、明细表格和托盘弹窗；Rust 后端负责读取本地日志、调用/封装 ccusage 的 Claude 与 Codex 统计能力、维护本地缓存、执行异常检测、触发系统通知。这样既能保持桌面 App 的轻量体验，又能复用 Web 技术快速迭代 UI。

架构上要特别加一层 `ccusage adapter`，不要让 UI 或业务逻辑直接依赖 ccusage 内部结构。这个 adapter 对上暴露稳定的数据模型，例如 `DailyUsageSummary`、`AgentBreakdown`、`ModelBreakdown`、`ProjectBreakdown`、`SessionSummary`；对下再调用 ccusage Rust crate 或 fork 出来的 core API。这样即使上游 ccusage 内部变动，也只需要改 adapter 层。

后台刷新第一版不要做实时文件监听，建议做简单轮询：默认每 15 分钟刷新一次，用户可选 5/15/30/60 分钟。每次刷新时默认使用 embedded/offline pricing，避免 GUI 版继承 CLI 当前的慢启动问题。macOS 使用菜单栏，Windows 使用系统托盘，点击后打开主窗口。

## 核心功能与页面结构

第一版建议分成四个核心区域：**托盘/菜单栏、Dashboard、Breakdown、Reports/Settings**。托盘是产品入口，展示今日成本、本月成本、最近刷新时间和当前状态；如果检测到异常，托盘状态可以变色或显示简短提示。点击托盘打开主窗口，不要求用户接触终端、命令参数或配置文件。

Dashboard 是默认首页，聚焦“快速知道现在是否正常”：今日成本、本周成本、本月成本、今日 token、与过去 7 天均值对比、最近一次异常提示。下面放一张日趋势图，以及 Top 项目、Top 模型、Top Agent 三个小榜单。用户不需要理解 cache read/cache create 等细节，首页只显示最容易理解的总成本、总 token 和变化趋势。

Breakdown 页回答“钱花在哪”：按项目、模型、agent 维度拆分，支持日期范围切换。Reports 页提供更接近 ccusage 的明细能力，例如 daily、monthly、session 表格，但不作为首页。Settings 页处理本地日志路径、刷新频率、通知开关、预算阈值、offline pricing 状态、开机启动。MVP 支持 Claude Code + Codex，其他 agent 显示为“未来支持”。

## 提醒策略与异常检测

第一版提醒策略采用“默认安静、异常才打扰”。默认只开启异常型提醒，预算提醒和实时活跃提醒可配置但默认关闭。异常型提醒不要求用户先设置预算，而是基于本地历史数据自动计算基线，例如过去 7 天日均成本、日均 token、项目成本分布和模型成本分布。当今日成本或 token 明显高于历史均值时，才触发系统通知。

MVP 可以先实现三类规则。第一类是日成本异常：今日成本超过过去 7 天均值的 2 倍，且绝对金额超过一个很小的下限，避免 `$0.01 → $0.03` 这种误报。第二类是 token 异常：今日 token 超过 7 日均值的 2 倍。第三类是来源异常：某个项目、模型或 agent 占今日成本超过 60%，且相比历史占比明显升高。通知文案要解释原因，例如：“今日成本 $8.42，是 7 日均值的 2.3 倍，主要来自 project-x / Codex。”

预算提醒提供今日预算和月度预算两个选项，用户设置后才启用。实时活跃提醒第一版只做轻量版本，例如当前 session 或 block 消耗速度异常时提醒；如果 ccusage core 集成成本太高，可以推迟到第二版。

## 数据流、缓存与隐私边界

数据流坚持 **local-first**：App 只读取本机 Claude Code 和 Codex 的使用日志，在本地 Rust 后端完成解析、聚合、成本计算和异常检测。前端只接收后端整理后的结构化统计数据，不直接读取原始日志。默认不上传任何数据、不需要账号、不依赖云服务。README 和首次启动页要明确说明：“所有分析都在本机完成”。

后台刷新流程是：定时器触发刷新 → adapter 调用 ccusage core 读取 Claude/Codex 数据 → 使用 embedded/offline pricing 计算成本 → 生成 daily/session/model/project breakdown → 写入本地轻量缓存 → 更新托盘状态 → 检查异常规则 → 必要时发送系统通知。缓存可以先用 SQLite 或简单 JSON 文件；更推荐 SQLite，因为后续做趋势、去重、增量刷新和设置管理会更稳。

本地缓存只保存聚合数据，尽量避免保存 prompt、完整文件路径、原始消息内容。项目名可以默认使用 ccusage 解析出的项目标识，但提供“项目别名”和“隐藏敏感路径”选项。错误日志也要注意脱敏，避免把用户本地路径或项目名直接写进可分享日志。

## 错误处理、首次启动与测试策略

首次启动要把“非技术用户可能遇到的失败”产品化处理。App 打开后先自动检测 Claude Code 和 Codex 日志路径，如果找到数据，就直接进入 Dashboard；如果没找到，则显示引导页，说明当前未检测到支持的数据源，并提供“重新扫描”“手动选择日志目录”“查看支持的数据源”三个入口。不要把底层错误直接暴露成 stack trace 或 CLI stderr。

错误处理要分层：日志路径不存在、无权限、无数据、日志格式不兼容、pricing 缺失、后台刷新失败、通知权限未开启，都应有用户可理解的状态。比如“未找到 Codex 日志”不是错误，而是一个灰色数据源状态；“无法读取 Claude 日志目录”才需要提示用户授权或手动选择。后台刷新失败不应打断 UI，只显示最近成功刷新时间和轻量错误提示。

测试上建议三层。Rust 后端做 fixture-based 测试，覆盖 Claude/Codex 日志解析、聚合、异常规则、缓存读写。前端做组件测试，覆盖 Dashboard 空状态、异常状态、预算状态和图表数据渲染。端到端测试至少覆盖首次启动、发现数据、托盘状态更新、通知触发、设置修改。跨平台需要专门维护 macOS/Windows 的路径和通知行为测试清单。

## 不做范围

第一版明确不做以下内容：

- 团队多人协作；
- 云同步；
- 账号系统；
- SaaS Dashboard；
- 全 agent 支持；
- 复杂预算审批；
- 原始 prompt 搜索；
- 企业级报表导出；
- 模型价格编辑器；
- 实时文件监听作为唯一刷新机制。

这些能力可以作为后续版本探索，但不应进入 MVP。

## 推荐后续步骤

1. 评估 ccusage Rust core 当前是否适合作为 library 集成，确认哪些 API 需要 adapter/fork。
2. 初始化独立 Tauri 2 项目，先实现 macOS + Windows 基础窗口、托盘和通知权限。
3. 定义 GUI 使用的稳定数据模型，不直接暴露 ccusage 内部结构。
4. 实现 Claude Code + Codex 的本地数据读取和 daily summary。
5. 建立 SQLite 缓存和刷新轮询机制。
6. 实现 Dashboard 首页和托盘成本状态。
7. 实现异常检测规则和默认通知。
8. 打磨首次启动、无数据、无权限等空状态。

## 一句话总结

这个项目值得做，但第一版不应该追求“完整 GUI 版 ccusage”。更好的切入点是：**开源、本地优先、常驻提醒优先的个人 AI 编程成本监控器，MVP 支持 Claude Code + Codex，使用 Tauri + Rust core 集成实现桌面体验。**
